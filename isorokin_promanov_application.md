**ВСОД "Улей"**

“Всероссийская Система Оповещения Детей "Улей"”

**ПРОБЛЕМНОЕ ПОЛЕ**

Система индивидуального оповещения учеников и педагогического состава учебного заведения в случае возникновения террористической угрозы или пожарной опасности. 

** ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ **

Продукт позволит повысить скорость реакции общества на черезвучайные ситуации, такие как пожар или террористический акт. К выделяемым группам относятся:

* Учащиеся средней и старшей школы
* Учащиеся вузов
* Преподаватели

**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]** 

Продукт разрабатывается под все известные операционные системы в данный момент и к моменту сдачи должен существовать в виде версий для следующих конфигураций:

* OS – версия 11 и выше, 10 Гб свободного места на гаджете
* Android – версия Nougat (Android 7) и выше, 12 Гб свободного места, 3 Гб оперативной памяти

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**

Программный продукт должен обеспечивать:
* Регистрацию пользователей по одноразовым кодам приглашения с присвоением роли
(ученик / учитель / диспетчер)
* Индивидуальную аутентификацию по токену (Bearer-токен)
* Отправку сигналов тревоги трёх типов: пожар, террористическая угроза, беспилотник
* Подсчёт «веса доверия» сигналов (учитель имеет фиксированный высокий вес, ученик —
настраиваемый)
* Автоматическое определение координат первого сигнала и возможность обновления
точки учителем
* Подтверждение тревоги диспетчером с оповещением всех учеников школы в радиусе 500
метров
* Передачу геолокации устройства на сервер
* Получение списка активных оповещений пользователем
* Веб-панель диспетчера для мониторинга тревог и подтверждения
**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]**

*	Java / Android Studio – для разработки Android-версии
*	Swift / XCode – для разработки iOS-версии
*	HTML / CSS / JS / Django / jQuery – для разработки веб-версии
*	PostgreSQL

**[ ЭТАПЫ РАЗРАБОТКИ ]**

* Проектирование архитектуры и схемы базы данных

подтверждение)
* Разработка веб-панели диспетчера
* Разработка мобильного приложения (Flutter): регистрация, кнопки тревоги, геолокация,
уведомления
* Интеграция клиента и сервера, тестирование сценариев
* Доработка интерфейса и подготовка демонстрации
* Подготовка проекта к защите / участию в конкурсах и олимпиадах

**[ ВОЗМОЖНЫЕ РИСКИ ]**

* Сложности с получением точных координат в помещениях школы (ослабление GPS-
сигнала)
* Необходимость обучения пользователей и проведения тренировок
* Риски ложных срабатываний (минимизируются системой «веса доверия» и
подтверждением диспетчера)
* Ограничения по времени на полноценную разработку мобильного клиента
* Возможные изменения требований со стороны образовательных учреждений при
реальном внедрении
