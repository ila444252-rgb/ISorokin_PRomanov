## Сценарий 1 — Регистрация пользователя

1. Пользователь открывает мобильное приложение «Улей».
2. Приложение предлагает ввести имя и одноразовый код приглашения.
3. Пользователь вводит данные и нажимает «Зарегистрироваться».
4. Если код не существует, уже использован или некорректен — система сообщает об ошибке и предлагает ввести код заново.
5. Если код действителен, сервер создаёт учётную запись, присваивает роль (ученик / учитель / диспетчер) и школу из кода, генерирует токен.
6. Токен сохраняется на устройстве пользователя.
7. Приложение сообщает об успешной регистрации и переходит на главный экран.
8. Запускается Сценарий 2 — Работа с главным экраном.

---

## Сценарий 2 — Работа с главным экраном

1. Пользователь видит главный экран с кнопками тревог: «Пожар», «Террор», «Дрон».
2. В зависимости от роли отображаются дополнительные элементы:
   - Ученик / учитель — кнопки отправки сигнала и статус геолокации.
   - Диспетчер — доступ к списку активных тревог и кнопке подтверждения.
3. Приложение в фоне периодически отправляет текущие координаты на сервер.
4. Пользователь может перейти к проверке личных оповещений (Сценарий 5).

---

## Сценарий 3 — Отправка сигнала тревоги

1. Пользователь (ученик или учитель) нажимает одну из кнопок тревоги.
2. Приложение отправляет на сервер запрос с типом тревоги и токеном авторизации.
3. Если токен недействителен — показывается ошибка авторизации.
4. Если пользователь — диспетчер, система запрещает отправку сигнала.
5. При успешной отправке сервер:
   - фиксирует сигнал;
   - учитывает «вес доверия» (учитель — высокий фиксированный вес, ученик — настраиваемый);
   - при наличии координат записывает/обновляет точку тревоги.
6. Пользователю показывается результат: количество сигналов, суммарный вес, статус подтверждения.
7. Если вес достиг порога — тревога считается подтверждённой на стороне сервера.

---

## Сценарий 4 — Подтверждение тревоги диспетчером

1. Диспетчер открывает список активных тревог своей школы.
2. Для каждой тревоги отображаются: тип, количество сигналов, суммарный вес, статус.
3. Диспетчер выбирает тревогу и нажимает «Подтвердить».
4. Сервер находит точку тревоги и всех учеников школы, находящихся в радиусе 500 метров.
5. Найденные ученики помечаются как оповещённые.
6. Диспетчеру возвращается список оповещённых устройств.
7. Приложение обновляет статус тревоги.

---

## Сценарий 5 — Получение оповещений

1. Пользователь (ученик) нажимает «Проверить оповещения» или приложение проверяет их автоматически.
2. Приложение запрашивает у сервера список тревог, по которым пользователь был оповещён.
3. Если список пуст — показывается сообщение «Активных оповещений нет».
4. Если есть тревоги — отображается предупреждающий экран с типом угрозы и рекомендацией к действиям (покинуть здание / забаррикадироваться).
5. Пользователь может отметить, что ознакомился с оповещением.

---

## Сценарий 6 — Передача геолокации

1. При запуске приложения и периодически во время работы запрашиваются координаты устройства.
2. При успешном получении координат они отправляются на сервер вместе с токеном.
3. Сервер сохраняет или обновляет последние известные координаты устройства.
4. Если геолокация недоступна — приложение продолжает работать, но точка тревоги от этого устройства не будет установлена.

---

## Сценарий 7 — Работа диспетчера в веб-панели

1. Диспетчер открывает веб-панель и вводит свой токен.
2. Нажимает «Загрузить» — получает актуальный список тревог школы.
3. Видит по каждой тревоге: тип, количество сигналов, вес, статус подтверждения.
4. Может нажать «Подтвердить» у нужной тревоги (Сценарий 4).
5. В перспективе на карте отображаются точки активных тревог.
6. Панель может автоматически обновлять данные через заданный интервал.
